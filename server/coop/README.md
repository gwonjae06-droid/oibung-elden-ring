# 오든링 2인 협동: 연결 기반 1단계

현재는 방/프로토콜 기반입니다. 실제 보스 전투 어댑터와 게임 메뉴 연결은 아직 없습니다.
방 서버가 실행돼도 기존 게임에 협동 플레이가 활성화되지는 않습니다.
마크 모드 프로젝트와 무관하며 기존 싱글플레이 파일을 수정하지 않습니다.

## 실행
Node.js 20 이상에서 이 폴더로 이동한 뒤 `npm install`, `npm test`, `npm start`를 실행합니다.
WebSocket 주소는 `ws://localhost:8080/coop`, 상태 조회는 `http://localhost:8080/health`입니다.
`src/coop-client.mjs`는 브라우저용 연결 모듈이며 기존 HTML에서 아직 불러오지 않습니다.
외부 HTTPS 게임에 연결하려면 HTTPS/WSS를 제공하는 별도 Node.js 서버 호스팅이 필요합니다.
GitHub Pages에 서버 파일을 올리는 것만으로 서버가 실행되지는 않습니다.
배포 시 ALLOWED_ORIGINS에 허용할 게임 출처를 정확히 설정하세요. 예: https://gwonjae06-droid.github.io
PORT는 호스팅 환경의 값을 사용합니다. 유료 서비스나 배포는 생성하지 않았습니다.

## 현재 동작
2인 방 생성·입장·준비·방장 종료, 접속별 서버 할당 ID, 메시지 크기 제한, 출처 검사, 요청 속도 제한.
진짜 전투 어댑터가 없으므로 start는 BATTLE_NOT_CONNECTED를 반환합니다.
테스트의 battleFactory는 단위 테스트 대역이며 실제 전투 구현이 아닙니다.
전투 중 동료가 나가면 로비로 돌아가며, 자동 재접속·방장 이전·계정 인증은 아직 없습니다.
방 코드는 친구 초대용이며 강력한 사용자 인증을 대체하지 않습니다.

## 검증
rooms.test.mjs는 Node 내장 테스트로 실행합니다. ws 패키지 설치와 실제 브라우저/WebSocket 연결은 별도 검증 대상입니다.
package-lock.json은 아직 생성하지 않았으며 npm 설치 후 의존성 감사가 필요합니다.
다음 단계는 기존 단일-player 엔진을 2인 공용 보스 엔진으로 분리하는 것입니다.
보스 시간은 방당 한 번만 진행하고 각 플레이어의 행동·피해·사망을 개별 처리해야 합니다.
