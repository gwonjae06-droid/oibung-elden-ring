# 최규원 — The Greatest Show of My Life

첨부 통합 기획서의 최종 HP 분배표를 기준으로 구현한다. 본문에 남아 있던 600HP 표기 대신 5~10수 700HP, 11수 1,000HP를 적용한다. 업로드 원본이 곡당 약 179초인 점을 확인했고, 사용자가 목표 길이 편집을 선택하여 원본을 보존한 별도 게임용 MP3를 만들었다.

| 구간 | 시작 HP | 종료 HP | 게임용 파일 | 목표 길이 |
|---|---:|---:|---|---:|
| 현역~4수 | 7,000 | 6,000 | 기존 패턴과 낮은 프롤로그 BGM | 직접 피해 250씩 |
| 5수 · 턴제 | 6,000 | 5,300 | gyuwon5.mp3 | 48초 |
| 6수 · 러닝 | 5,300 | 4,600 | gyuwon6.mp3 | 44초 |
| 7수 · 유닛전 | 4,600 | 3,900 | gyuwon7.mp3 | 48초 |
| 8수 · 리듬 | 3,900 | 3,200 | gyuwon8.mp3 | 48초 |
| 9수 · 격투 | 3,200 | 2,500 | gyuwon9.mp3 | 44초 |
| 10수 · 슈팅 | 2,500 | 1,800 | gyuwon10.mp3 | 48초 |
| 11수 · 피날레 | 1,800 | 800 | gyuwon11.mp3 | 70초 |
| 마지막 인사 | 800 | 0 | gyuwonending.mp3 | 45초 |

음악 본편 350초, 슬픈 엔딩 포함 395초이다. MP3 프레임 패딩 때문에 브라우저 메타데이터 길이에 수십 ms 차이가 생길 수 있다. 실제 재생이 정상일 때에는 목표 길이 타이머로 자르지 않고 미디어의 정상 종료를 기다린다.

## 전투와 음악의 소유권

- 1~4수는 실제 무기 적중으로만 각각 250HP를 쓴다. 시험과 채점 합계는 2.6초이며 성적은 HP를 바꾸지 않는다.
- 5~11수의 적중은 공연 점수와 시각 반응을 만든다. 직접 피해와 DoT로 연차를 건너뛰거나 HP를 내릴 수 없다.
- 각 곡의 종료는 한 번만 수락한다. 1.1초 동안 실제 HP와 표시값을 함께 목표값으로 보간하며 이 감소량은 누적 피해 통계에 들어가지 않는다.
- 장르 교체 중 입력과 기존 피해 판정을 잠근다. 마지막 플레이어 공격 자세는 마무리한 뒤 소품, 탄환, 유닛을 정리한다. 다음 입장 위치로는 보간 이동한다.
- 음악 `currentTime`이 전투·조명·모션·자막·노트의 기준이다. 로딩이나 버퍼링 중에는 해당 시간에 묶인 게임도 멈춘다. 정상 미디어는 `ended` 전까지 종료하지 않는다.
- 일시정지는 음원을 멈추고 위치를 보존한다. 음소거는 재생 시계를 유지한다. 종료·재시작 시 이전 음원의 종료 콜백은 무효다.
- 재생 거절, 디코딩 오류, 6초 이상 진행하지 않는 음원은 같은 위치에서 무음 대체 시계로 전환한다. 대체 길이는 알려진 실제 길이 또는 표의 길이다. 현재 곡과 다음 한 곡만 준비한다.
- 뮤지컬 첫 치명적 실패에는 연차마다 한 차례 짧은 회복 기회를 제공한다. 반복 실패는 기존 패배로 처리한다. 약화된 피해량과 회복약은 유지한다.

턴제는 접근 동작과 근접 접촉, 러닝 투척은 날아가는 탄환, 유닛전은 실제 부대 이동, 격투는 사거리와 지연된 타격, 슈팅은 실제 탄환 충돌, 리듬은 시간 판정으로 점수를 얻는다. 허공 공격은 점수를 주지 않는다. 원거리 총격·오토바이 돌진 효과음은 실제 발동 순간에 업로드된 `foisal72-gun-fire-346766.mp3`와 `bikepass.mp3`를 사용한다.

## 음악과 자막 제작 자료

원본 파일명을 `gyuwon-song-data.mjs`의 `source`에 보존한다. `assets/music/gyuwon-edit-manifest.json`에 원본 추출 범위, 편집본 위치, 짧은 교차 페이드와 피치를 보존하는 속도 조정 비율을 기록했다. 마스터는 -16 LUFS / -1.5dB true-peak 목표로 정리했다. 대표 후렴과 마지막 인사를 우선 보존하며 반복 구절과 긴 간주를 줄였다. 복도에는 원본 엔딩의 후주를 별도 `gyuwoncoda.mp3`로 사용한다.

편집 재현에는 선택적 개발 도구 `ffmpeg-static`이 필요하다. 런타임에는 이 도구나 음성 분석 모델을 다운로드하지 않는다.

```text
npm install --no-save --package-lock=false ffmpeg-static
node scripts/edit-gyuwon-music.mjs
node scripts/chart-gyuwon-beats.mjs
```

리듬 차트는 편집된 PCM의 강박 에너지와 무음 구간을 분석한 결과다. 자막은 편집본의 구절 인식 시간과 제공 가사 대조를 바탕으로 영어와 한국어를 별도 줄에 표시한다. 간주에는 자막을 숨긴다. 오디오를 바꾸면 차트를 다시 만들고 자막 시간도 보정해야 한다.

**검수 한계:** 음성 인식은 노래에서 단어 경계를 잘못 추정할 수 있다. 자동 구절 분석과 가사 대조를 수행했으나, 사람의 전곡 청취를 통한 편집 접합부·자막 미세 싱크 승인은 아직 없다. 신시사이저나 브라우저 TTS가 제공된 보컬을 덮어쓰지 않는다.

## 마지막 장면

11수 종료 시 800HP에서 45초 엔딩곡으로 바뀐다. 전투는 종료하고 조명·자세·카메라가 가라앉는다. UI는 후반부에 숨겨지고 마지막 피아노와 함께 암전한다. 남은 800HP는 마지막 구간에 0이 된다.

정규 여정의 승리와 불꽃은 한 번 저장한 뒤 보상 클릭을 기다리지 않고 종결로 연결한다. 메인의 다섯 문양, 마지막 붉은 점등, 갈라지는 석판, 아침빛으로 향하는 복도, 검·가면·주사위·붉은 날개·답안지의 흔적, 제목과 크레딧을 순서대로 보여 준다. 새 보스와 사용자 스킵 기능은 없다. 숨김 탭에서는 연출 시간이 멈추며 종결 전용 감시 시간은 충분한 여유를 둔다.

## 검증

- 변경 기능 관련 Node 검사 37개 통과.
- 전체 Node 검사 2,138개 중 2,110개 통과, 28개 실패. 변경 전 `471dead` 별도 작업 폴더에서는 2,132개 중 2,103개 통과, 29개 실패였으며 변경 후 실패는 원본 실패 목록 안에 있다. 다른 보스의 기존 실패를 이 작업에서 수정했다고 주장하지 않는다.
- Windows Edge 실제 WebGL: 일곱 곡 각각의 네이티브 종료 이벤트, 정확한 HP 목표, 키보드 공격과 방어, 일시정지·재개·음소거, 800HP 엔딩, 문양·복도·크레딧과 844×390 배치를 확인했다. 전체 약 8~10분의 자연 플레이를 대신하는 검사는 아니며 후반 종료 이벤트 검사에는 음원 탐색을 사용했다.
- 동일 데스크톱 자동 검사에서 새 무대는 약 197~210 드로콜 / 7.6만~8만 삼각형, 프레임 간격 P95 약 5.6~5.7ms였다. 물리적 휴대폰 FPS, 실제 오디오 출력 지연과 전 구간 자연 플레이 밸런스는 미측정이다. 이 수치는 특정 실행 환경의 관측값이며 모바일 성능 보장이 아니다.
- `scripts/gyuwon-musical-qa.mjs`와 `Gyuwon musical` 워크플로가 스크린샷·상태 보고서를 저장한다.

낮은 프레임에서 연출이 늘어지는 고정 프레임 누적을 제거했다. 엔딩 RAF 콜백을 초당 5회로 제한한 추가 검사에서도 약 19.3초에 끝났다. 곡 종료 후 HP 보간과 오류 대체 시계도 활성 상태의 실제 경과 시간을 사용하고, 일시정지 시간은 제외한다.
