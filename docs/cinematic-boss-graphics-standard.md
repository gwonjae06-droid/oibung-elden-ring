# 오든링: 모든 보스 공통 실사풍 시네마틱 그래픽 표준

> 적용 대상: **이권재 · 오슬우 · 박성원 · 배서준 · 향후 최규원**, 이후 모든 신규 보스와 필드.  
> 엔진: HTML + JavaScript + Three.js/WebGL. **Blender 제작 단계는 포함하지 않는다.**  
> 목표: 단순 밝기·폴리곤 수 증가가 아니라 **같은 물리적 공간에서 실제 사물이 함께 존재하는 듯한 질감, 광학, 움직임, 충격 반응**.

## 1. 적용된 공통 런타임

- `src/cinematic-graphics.mjs`: 보스별 영화적 색온도·노출·환경반사 프로필, PBR 텍스처팩, 노멀/거칠기 데이터, 성능 품질 등급.
- `src/cinematic-impact-fx.mjs`: 보스 타격·피격과 충격 사건에 반응하는 3D 물리 질감 파편(오브젝트 풀 + 중력 + 자연 감쇠).
- 네 보스 전투 진입점(`arena.mjs`, `clown-battle.mjs`, `dice-battle.mjs`, `blood-battle.mjs`)에 적용하며 기존 보스별 외형·사운드·카메라·환경 업데이트를 유지.
- 새로운 엔진은 **전투 이벤트를 읽기만 한다.** 피해량, 회피 무적, 히트박스, 경고·발동 판정, 적 AI를 절대 변경하지 않는다.
- 실사 풍의 PBR 외형은 Blender 없이 JavaScript에서 생성한 결정론적 표면 데이터와 기존 텍스처·메시를 합성한다.

## 2. 표면 표현의 의무사항

| 표면 | 물리적 요소 | 반드시 보여야 하는 것 |
|---|---|---|
| 석재/성당 대리석 | 거칠기·미세한 깨짐·정맥 같은 무늬 | 큰 표면이 플라스틱처럼 반짝이지 않음 |
| 금속/왕검/카지노 황동 | 금속성·서로 다른 거칠기·날카로운 명암 | 시선·조명 방향에 따라 하이라이트 이동 |
| 서커스 벨벳/의복 | 섬유 방향·부드러운 반사·주름 | 움직임과 그림자로 천의 두께감 확보 |
| 목재/가구 | 나뭇결·도장 마모·넓은 확산광 | 카지노와 학원 가구의 차별화 |
| 피부/얼굴 | 미세한 노멀·반사 최소화·입체 그림자 | 얼굴 사진 평면 부착 방지. 기존 표정·모션 유지 |
| 피/체액 | 낮은 거칠기·점성 표현·가변 반사 | 액체의 속도·농도·수면 반사 구분 |

- 기존에 사진이나 진짜 PBR 텍스처가 있는 모델은 **덮어쓰지 않는다**. 없는 맵만 생성해 보충한다.
- `MeshBasicMaterial` 경고, 판정 예고, 투사체 핵심 색상은 물리 표면화에서 제외한다. 타격 및 위험 인지성이 항상 우선이다.
- 고품질 데스크톱/저사양 모바일은 텍스처 해상도·추가 조명·이펙트 개수를 분리한다. 고급 효과를 모든 기기에 강제하지 않는다.
- 실제 고정밀 인체 메시가 없는 곳은 **완전한 포토리얼리즘을 보장하지 않는다**. 코드 기반 지오메트리 개선을 점진적으로 수행한다.

## 3. 무대 조명과 색의 역할

- 실사체는 '더 어두운 화면'이 아니다. **물체가 볼 수 있을 만큼 충분히 밝고**, 주요 광원 방향/색온도/감쇠가 자연스럽게 느껴져야 한다.
- 이권재: 차가운 달빛·무광 풍화석·녹슨 금속. 2페이즈 붉은 봉인이 별도 광학적 사건.
- 오슬우: 따뜻한 백열전구와 황동·벨벳. 2페이즈 천막 왜곡과 자홍/청록 공연광. 검은 배경에 네온만 떠 있는 느낌 금지.
- 박성원: 고급 카지노 목재·황동·유리 반사. 1페이즈 금빛, 2페이즈 경보, 3페이즈 균열과 무너지는 광원.
- 배서준: 백색 대리석·차가운 자연 채광·유리색 반사·진홍 혈해. 대성당을 과도한 붉은 필터로 덮지 않는다.
- 최규원: 아래 독립 명세 준수.

## 4. 공격/애니메이션의 영화적 기준

- **예비동작 → 힘의 축적 → 실제 접촉/피해 판정 → 관성 및 잔동작 → 회복 자세**로 구분한다.
- 투사체/몸/머리/손이 갑자기 출현하거나 순간 이동하는 대신, 발동 원점과 방향을 볼 수 있어야 한다.
- 소형 물리 파편과 먼지·충격음·카메라 반응은 **접촉 이벤트 이후** 재생한다. 피해 판정을 앞서거나 가리지 않는다.
- 효과의 발광/흔들림은 스팸하지 않고 0.1~0.5초 이내 피크 후 감쇠한다. 사용자의 키 입력과 HUD를 방해하지 않는다.
- 고강도 섬광/블러/카메라 흔들림의 사용 빈도를 제한한다. 접근성 설정이 활성화된 기기에서는 최소화한다.

## 5. 최규원 보스 제작 시 의무 지침

최규원은 **기숙학원/교실의 익숙한 현실이 철학적 공포로 변하는 마지막 보스**다. 해당 공간의 배경 모델을 Blender에서 작업하지 말고 웹 기반 모듈로 생성한다.

**1페이즈 — 지나치게 사실적인 현실:** 형광등 아래 책상, 지문과 스크래치가 있는 유리창, 쓰인 칠판, 낡은 교재와 먼지. 서늘한 명암과 자연스러운 움직임. 과장된 8비트/카툰 텍스처 금지.

**2페이즈 — 현실의 균열:** 교실 타일, 책상, 시계, 종이 등 이미 실사풍으로 만들어 둔 소재들이 **기하학적으로 뒤틀리고 중력/반사 방향이 변하는** 연출. 단순한 화면 검정/붉게 칠하기보다 실제 물체가 변형되어 의미를 가진 공간 변화.

**최종 연출 — 철학적 선택과 변모:** 캐릭터의 변신은 관절·질량·천·환경 반응과 연결한다. 새 움직임이 공격 판정보다 앞서거나 뒤처지지 않아야 한다. 희생/선택 등 서사 소재는 컷씬과 전장 물체의 변화로 전달한다.

**최규원 구현 체크리스트:**
- `CINEMATIC_PROFILES.gyuwon`으로 공통 라이팅·재질·파편 시스템 적용
- 고유 `src/gyuwon-*.mjs` 모듈에서 학원 건축·보스 리그·페이즈·이펙트를 분리, 신규 로딩/종료 후 자원 해제
- 장면의 물체·모션만 시뮬레이션에 부속: 공격 판정/히트박스는 새 게임 로직에서 별도 관리
- 1→2페이즈 및 엔딩까지 장면 테스트(실제 브라우저 렌더/모바일/재도전/일시정지) 마련
- 기존 네 보스보다 무조건 더 어둡거나 더 많은 투사체로 난이도를 표현하지 않음

**현재 최규원 보스는 아직 구현되어 있지 않다.** 위 내용은 이후 개발 시 따라야 할 실제 코드 인터페이스·아트 디렉션이며 최규원을 플레이할 수 있다는 뜻이 아니다.

## 6. 검증과 성능 제한

1. 공통 그래픽 코드의 물리 표면/텍스처 결정론과 메모리 해제를 Node 단위 테스트.
2. 각 보스 진입/페이즈/재시작의 브라우저 콘솔·WebGL 드로콜·화면 캡처 확인.
3. 모바일에서 배경 광원을 무작정 늘리지 않고 64px 표면, 파편 24개 한계, 그림자 없는 보조광 사용.
4. 전투 판정·회피·보스 HP는 시각 모듈에서 건드리지 않으며 전환 전후 동일성을 테스트.
5. 사용자 체감 FPS(실기기 기준)와 가독성은 자동 검사와 별개로 수동 검증.

이 문서는 **새로운 보스를 추가할 때도 적용되는 영구 개발 규칙**이다. 보스별 임의 스타일링 때문에 공통 실사풍 원칙을 깨지 않는다.
