# Skill effect and boss audio disposal on main

The boss-sfx implementation is copied from branch commit e46b4183f77fb5394d3ceb28dd801215882e0df1; no branch merge is performed. The branch's eleven dedicated boss disposal tests are not copied by this patch; their earlier isolated pass is historical evidence, not a current full-repository test result. Existing main tests are preserved.

createSkillFx now returns idempotent terminal dispose() and disposed. Explicit disposal calls bossSfx.dispose(), playerFx.dispose(), and child terminal disposers where available, falling back to clear/hide for children that do not expose them. It clears transient state, detaches only its own effect/circus/impact roots, and deduplicates their geometry/material/direct texture/shadow-target release. Borrowed scene nodes are not destroyed. clear() remains reusable before disposal; event/update/ring/emit paths are inert afterwards. Child synchronous errors, rejections and malformed asynchronous cleanup reports are collected in the completion report without skipping other cleanup.

The owned particle geometry also bridges existing whole-scene teardown into terminal boss-audio disposal. Delegated cleanup does not detach scene nodes or release GPU objects again while the parent is traversing them. In that path playerFx.clear() is used rather than structural player disposal; the player's own trail-geometry bridge retires player audio when the parent reaches it. This relies on the parent actually completing the whole-scene release and is not a substitute for doing so. The bridge does not make the parent await or aggregate these asynchronous reports.

Validation: six new tests and syntax checks passed in an isolated Node VM using the production skill-fx function body with Three.js and all child-factory/data dependencies replaced by doubles. These tests cover ownership orchestration, not real rendering, particle math, actual audio, live DOM, or the full repository npm test.

Still pending: parent session disposers should explicitly call and await child disposers rather than rely on geometry bridges; common app audio ownership and close deadlines; robust partial-construction rollback; exception-safe secondary battle teardown; hidden state/async work in remaining child modules; factories/remounting and the full browser acceptance matrix. Default boss contexts are per-instance fallbacks and injected contexts are borrowed, not an implemented single app-wide audio service. A context-close Promise that never settles can still delay explicit disposal completion. No complete-game-shutdown or measured leak-free claim is made.
