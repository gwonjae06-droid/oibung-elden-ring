# Player effect/audio disposal on main

This revision copies the player-sound implementation and its seven tests from branch commit 8e480daf873cf86a4e9d4836fff0c9c038417a5b and adds player-polish ownership/disposal. It does not import the boss-sfx branch change or merge that branch. Future writes target main as requested.

createPlayerPolish now owns only the trail, decoration meshes/groups, and geometry/material objects it creates. Explicit dispose() synchronously marks the effect terminal, invokes sound.dispose(), detaches its owned nodes and releases unique owned resources. The borrowed player rig, bones, weapon groups and original cards are not destroyed. clear() remains reusable. Retained event/update/clear calls after disposal do nothing. makeSound and soundOptions are injectable for ownership tests and eventual app audio routing. Disposal reports child audio and resource failures without rejecting the completion Promise. The existing animation logic is retained; restoring a borrowed model's last animation pose is not implemented here.

A bridge listens for disposal of the owned trail geometry. Existing whole-scene teardown in the main/secondary renderers can therefore retire player audio even before they explicitly invoke the new player-polish disposer. In this delegated path, it does not remove scene nodes while a parent traverses them or dispose the other GPU resources again: the parent remains responsible for completing the whole-scene resource release. Disposing just the trail geometry alone is not a substitute for complete scene teardown. The bridge unregisters itself and is idempotent with explicit disposal. It does not make the parent await or aggregate the audio-close report.

Validation: six new tests passed in an isolated Node VM using the production player-polish function body with Three.js, sound and presentation-helper doubles. No WebGL/real Three.js or live audio was exercised. The seven imported player-sound tests passed in the earlier isolated run, not as a full repository run in this step. New tests use node:vm and do not require installing Three.js just to exercise these ownership mocks.

Still pending: bossSfx/skill-fx terminal wiring, other nested effect disposers, common app audio service and close deadlines, explicit session factories and remounting, partial-construction rollback, exception-safe secondary battle teardown, the full npm test and browser/acceptance matrix. Default player audio contexts remain per instance, not one shared app context. No claim of complete game shutdown or measured leak freedom is made.
