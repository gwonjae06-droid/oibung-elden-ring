# 카메라 시야와 고정 화면

2026-11-05. 맵의 삼각형을 매 프레임 여러 번 검사하던 방식 대신, 카메라와 인물 사이의 좁은 통로에 들어온 표면만 투명하게 표현한다.

- 맵 전체나 기둥 배치를 지우지 않는다. 보이는 표면 중 인물을 가리는 부분만 3.5% 불투명도까지 옅어지고 가장자리는 부드럽게 이어진다.
- Three.js alpha hashing을 사용한다. 일반 투명 물체의 정렬 오류나 맵 전체를 다시 그리는 추가 패스를 만들지 않는다.
- 지면은 유지한다. 보스, 플레이어, 공격 예고와 공격 이펙트는 맵 루트 밖에 둔다.
- 맵 삼각형 Raycaster 호출과 인스턴스 행렬 수정·복구가 모두 없어졌다. 카메라·대상 좌표는 매 화면 갱신하므로 빠르게 시점을 바꿔도 검사 주기를 기다리지 않는다.
- 공유 원본 재질은 보존하고 렌더 중에만 전용 재질을 사용한다. 원본의 단계별 색·발광·투명도 애니메이션과 기존 셰이더 콜백을 이어받고, 종료 시 원본을 복구하고 전용 재질을 해제한다.

메인 메뉴 또는 다른 보스전이 첫 전장을 덮으면, 첫 전장의 시계와 세션만 유지하고 보이지 않는 3D 화면은 다시 그리지 않는다. 다른 보스전의 렌더러와 첫 전장 렌더러가 동시에 GPU를 쓰던 낭비를 막는다.

## 실제 전투 연결

- 이권재: 성소, 외곽 기둥 14개, 외곽 배너.
- 오슬우: 현재 전투에서 사용하는 새 서커스의 커튼·기둥·천막·관객과 배너.
- 박성원: 카지노 맵과 먼 외곽 장식. 거인의 팔·손바닥·손가락도 플레이어 앞부분만 같은 방식으로 투명하게 표현한다. 손 체력바는 화면 폭의 16% 이내로 제한한다.
- 배서준: 흰 성당 구조물과 외곽 배너.

## 화면

네 전투 모두 1600×900, 16:9 투영을 사용한다. 브라우저 배율이나 모니터의 픽셀 배율에 따라 내부 렌더링 크기가 증가하지 않는다. 화면에 맞춰 가로·세로를 같은 비율로 확대·축소하고 남는 부분은 어두운 여백으로 둔다. HUD와 터치 조작은 이 전투 영역 안에 배치한다.

## 박성원 전장 정리

룰렛 간판은 z=-275, 점수판은 z=-282로 옮겨 안쪽 손님(r=150)과 바깥 관객(r=205) 뒤에 둔다. 금빛 파편은 r>=285, 외곽 배너는 r=280, 천장 장식도 외곽으로 옮긴다. 탁자 위 배경 스파크와 공중 칩 입자 생성기를 제거한다. 공격 판정과 공격 시각 효과는 유지한다.

## 검증

- 재질 공유·애니메이션·콜백·해제, 인스턴스 행렬 불변, 룰렛/관객 간격과 배경 입자 제거를 Node에서 검사한다.
- camera-clarity-smoke.mjs는 현재 네 맵의 8방향(총 32개)에서 가림 전·후 픽셀을 비교하고, 맵이 없는 기준 화면 대비 대상의 가시성을 확인한다.
- 실제 시작 경로와 세 보스 모달, 4:3·16:9·울트라와이드·작은 가로 화면 및 박성원 2페이즈를 WebGL에서 검사한다. 기존 camera-visibility-smoke.cjs도 같은 검증으로 연결된다.
- Windows Node 24에서 같은 성당/서커스 맵, 2대상, 80회 비교한 CPU 중앙값: 성당 7.06→0.117ms, 서커스 12.11→0.076ms. 가림 처리 부분의 측정이며, 전체 FPS나 실기기 휴대폰 성능을 의미하지 않는다.
