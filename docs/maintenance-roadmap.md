# 구조 개선 작업 현황

기준: 2026-11-03. 사용자가 요청한 구조 개선 1~5번을 코드와 자동 테스트 범위에서 처리했습니다. 실제 플레이 검증인 6번은 이번 요청에서 제외했습니다.

## 1. 기존 실패 테스트 23개 해결

이전 구현의 제목만 이동하는 연출, 체력 2400/1800, 이전 보드 좌표와 소스 문자열에 묶인 기대값을 현재 계약으로 옮겼습니다. 주사위의 비활성 공격을 검사하는 테스트는 해당 공격을 명시적으로 켜고, 경고 시간 검사는 이전 단계에서 소비한 시간을 중복 계산하지 않도록 수정했습니다. Three.js 대역에는 현재 사용하는 타입을 추가했습니다. 불의 고리는 마지막 보스 위치가 아니라 경고 생성 시점의 위치를 기준으로 검사합니다. 테스트를 삭제하거나 전투 수치를 바꾸지 않았습니다.

## 2. 세션별 전투 진행 상태

`battle-session.mjs`가 화면마다 독립 `createEncounterStore()`를 소유합니다. 재도전은 해당 화면의 게임 객체만 바꾸고 이전 진행 티켓을 무효화합니다. ID는 저장소 간에도 중복되지 않습니다. 기본전과 광대전의 실제 UI 경로는 `register:false`로 게임을 생성합니다. 주사위 세션도 자신의 보스 ID와 결과를 제공합니다. 협동 참가의 무기 선택은 현재 화면의 실제 무기를 우선 사용합니다. 과거 엔진 호출과 테스트를 위한 기본 전역 저장소 API는 호환용으로 유지합니다.

## 3. 자원 소유권과 실패 정리

세 전투의 시작을 초기화 작업 단위로 관리합니다. 기본 아레나도 렌더러 생성 이후 오류가 나면 생성 자원을 되돌립니다. 모델·주사위·광대·플레이어 효과·환경 생성자는 생성 중인 Three.js 자원을 추적하고 실패 시 분리된 자원과 자식 핸들까지 정리합니다. 성공하면 이 추적은 종료되고 기존 전투 종료 처리가 소유권을 이어받습니다.

장면 해제 코드는 특정 보스 모듈에서 독립시켰습니다. 공유 지오메트리·재질·텍스처를 중복 해제하지 않으며, 개별 해제 실패가 나머지 작업을 막지 않습니다. 타격 효과의 전역 입력 구독과 오디오에 종료 처리를 추가했고, 기본 아레나가 그 비동기 결과를 수집합니다. 주사위 사진 로딩은 종료 시 준비 대기를 완료하고 콜백을 해제합니다.

이 처리는 애플리케이션이 획득한 자원과 시험한 실패 지점에 대한 보장입니다. 제3자 라이브러리 생성자 내부에서 반환 전 발생하는 할당이나 실제 GPU 메모리 해제까지 측정한 것은 아닙니다.

## 4. UI 결합 제거

세 전투의 플레이어 체력·기력·회복약·무기·스킬·보스 생명 표시는 `renderSharedHud()`가 엔진 상태로 갱신합니다. 화면 효과, 음악, 보스 진행, 협동 무기 선택은 연결된 세션의 실제 상태를 우선 사용합니다. 시작·무기 선택·메뉴 복귀·일시정지·재개·종료는 명시적인 명령을 제공합니다.

이전 페이지와 테스트 대역에는 버튼 및 텍스트 호환 경로를 남겼습니다. DOM 관찰자는 화면 루트 발견과 표시 정리에 사용하며, 승패 판단의 원천으로 사용하지 않습니다.

## 5. 책임 분리와 코드 정리

무기 정의, 플레이어 행동·공격 타이밍·투사체·보상, 세션 상태, HUD, 프레임 루프, 일시정지, 이벤트·타이머, 초기화 및 자원 해제를 분리했습니다. 핵심 전투 파일인 `combat.mjs`, `clown-combat.mjs`, `player-combat.mjs`, `dice-player.mjs`를 포맷해 분기와 상태 변경을 추적하기 쉽게 했습니다.

- 생성자 실패 주입, 기본 아레나 초기화 실패, 자식 자원 중복 해제 방지, 해제 실패 격리와 타격 오디오 종료를 검사했습니다.
- 이전 플레이어 공통화 단계의 전후 비교에서는 네 무기와 세 보스 조합 14,400프레임의 비교 대상 상태가 일치했습니다.
- 실제 브라우저 플레이, 모바일 성능, 두 브라우저 협동 통신 및 GPU 메모리 측정은 이번 요청 범위에 포함하지 않았습니다.
