# Bounded cleanup completion for app and main runtime

The new cleanup-completion helper invokes cleanup immediately, handles synchronous failure and Promise rejection, cancels its deadline after settlement and returns fulfilled reports with errors and timeouts. Never-settling asynchronous work is reported as a timeout, not as proof of successful release. Late rejections are consumed and do not mutate the report after it has completed. Error entries carry label/error; inherited labeled entries and timeout entries are retained. Invalid deadlines are rejected before cleanup execution.

createArenaRuntime.dispose() now synchronously marks the runtime terminal and stops its frames/listeners/captures/timers, while returning one shared completion Promise. It waits for the onDispose return value and directly owned AudioContext.close results with a default per-task deadline of 2000ms. Synchronous resource cleanup failures are included. Other renderer/scene cleanup proceeds immediately; asynchronous onDispose implementations must perform structural scene/DOM invalidation synchronously before returning their Promise. They must not defer structural GPU cleanup until after an await.

bootstrapGame dispose()/disposeFeatures() now return the same Promise and include the completion returned by the arena and feature controls. Controls are invoked synchronously in the existing reverse-feature, transition, entry, arena order, then their asynchronous results are collected concurrently. A hung feature does not stop later cleanup invocation. Its default per-control deadline is 4000ms. Both APIs expose whenDisposed, which is null before disposal is requested and is the shared Promise afterwards. Existing callers may ignore the return value and still get synchronous invalidation. Late startup handles are reclaimed independently, but cannot retroactively be added to an already finished completion report. Same-document remounting remains unsupported.

Important scope limit: arena.mjs still returns no skillFx.dispose Promise from its existing onDispose callback, and secondary battle close paths remain unchanged. This revision does not register/discover every nested effect disposer. Geometry bridges still retire those audio backends where whole-scene teardown reaches them, but this report does not thereby prove all nested audio has completed. Explicit child registration/return propagation remains required. Permanent pagehide can request cleanup; the browser need not await it.

Validation: 11 targeted tests and syntax checks passed in an isolated Node directory using the revised helper/runtime/bootstrap plus a copy of the existing frame-loop and injected window/scene/audio/feature doubles. Tests include pending/rejected/never-settling closes, stable Promise identity, deadline cancellation, late rejection, startup cancellation and continuation after failures. Full npm test, real Three.js/browser/audio, memory measurements, BFCache and live-server acceptance tests were not run.
